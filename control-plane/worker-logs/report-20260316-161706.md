## Task: P0 LP APY calculation — 200289% displayed, should be ~0.2%

## Result: FIXED
Root cause identified and resolved in both ProtocolStats.tsx and Vault.tsx.

**Bug:** `borrowRateToUse * totalOIInWad * hoursPerYear * lpShare / hundredPercent` — multiplying two WAD-scale numbers (borrowRate × OI) without dividing by WAD. This leaves the result in WAD² scale (1e36 instead of 1e18), inflating APY by ~1e18.

**Fix:** Split into two steps:
1. `revenuePerHour = borrowRateToUse * totalOIInWad / WAD` (normalize WAD×WAD → WAD)
2. `projectedAnnualRevenue = revenuePerHour * hoursPerYear * lpShare / hundredPercent`

Also changed APY precision from raw bps to bpsTimes100/100 for 2-decimal precision.

**Bonus fix:** Vault.tsx `getVaultUtilization()` was comparing 6-decimal OI against WAD-scale TVL (always returned 0). Fixed to compare both in USDT 6-decimal format.

**Verification:**
- Node.js simulation with real on-chain values: OLD code → 200,289,356,757,914,112%, NEW code → 0.20%
- On-chain values: OI=$138,334 (6-dec), TVL=$60,503,000 (6-dec), borrow rate fallback 2e14 WAD
- getCurrentBorrowRate() reverts (market-specific rate unavailable), correctly falls back to BASE_BORROW_RATE
